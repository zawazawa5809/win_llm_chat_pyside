# Requirements Document

## Project Description (Input)

選択肢 C: ハイブリッド(中間案)を実装し、ユーザが任意の(複数もあり)ファイルをチャットに送信するかを選択できるようにし、「質問する」ボタンを廃止する。添付ファイルを使った指示や質問を通常のチャットに一本化する。

## Requirements

### Scope

- インスコープ: LLM Chat Client メインウィンドウにおける「添付」タブとメッセージ送信フロー、添付テキストのプロンプトへの組み込み方式、ヘルプ/表示文言の更新
- アウトオブスコープ: 添付テキスト抽出ロジック（`AttachmentManager` / `FileTextExtractor`）、添付検索アルゴリズム、セッション/履歴保存方式、LLM クライアント実装（接続設定やエンドポイント仕様）

### Functional Requirements

- FR-1 添付ファイルのチャット送信対象選択

  - ユーザは「添付」タブ上で、各添付ファイルごとに「次回以降の送信メッセージに含めるかどうか」を明示的に選択できること（複数選択可）
  - 選択状態は UI 上で一目で判別できること（例: チェックボックス、アイコン、行ハイライトなど）
  - 送信完了後、誤送信防止のため「今回メッセージに含めた添付」の選択状態は既定でクリアされること（継続利用が必要な場合のみユーザ操作で再選択する）

- FR-2 通常チャットへの添付コンテキスト統合

  - メインの送信操作（メッセージ入力欄＋「送信」ボタン）だけで、テキストと選択済み添付ファイルの両方を LLM に送れること
  - 選択された添付ファイルがある場合、LLM に送信されるプロンプトには少なくとも以下の情報を含めること:
    - ファイル名、サイズ、種別（MIME など）のメタデータ
    - 抽出済みテキスト本文（`AttachmentManager` が管理するテキストを利用）
  - 添付が 1 件も選択されていない場合、現行実装と同等の「テキストのみ送信」挙動となること

- FR-3 添付テキスト長の制御と警告

  - 1 回の送信で LLM に渡す添付テキストの総量には上限（ソフトリミット）を設け、超過分は切り詰めまたはサマリ化すること（具体的な上限値は実装時にコンフィグ可能とする）
  - 添付テキストが長すぎる場合、ユーザに対しステータスバーや UI 上の表示で「送信内容が一部省略される」旨を通知できること
  - 既存の `length_warning` フラグなどを活用し、過度なトークン消費を防ぐための設計を行うこと

- FR-4 「質問する」ボタンの廃止とフロー統合

  - 添付一覧 UI 上の「質問する」ボタンは廃止し、添付ファイルへの質問は通常チャット（メッセージ入力欄＋送信）を通じて行うスタイルに統一すること
  - ユーザが特定の添付に質問したい場合は、当該添付を選択し、メッセージ欄に自然文で質問を書いて送るだけで完結すること
  - 既存のヘルプ・ラベル・ツールチップなどに「質問する」ボタンを前提とした説明がある場合は、それらを本仕様に合わせて更新すること

- FR-5 既存機能との整合性

  - 添付ファイルの追加・削除・再抽出・一覧表示・検索など、既存の添付関連機能はハイブリッド送信対応後も動作を維持すること
  - 既存のファイル要約機能（「要約」ボタン等）がある場合、本仕様の導入により退行しないこと（必要に応じて実装方法のみ通常チャットフローに寄せる）
  - セッション切替、プロファイル切替、ストリーミング表示など他機能への副作用がないこと

### Non-Functional Requirements

- NFR-1 操作の分かりやすさ

  - 初見ユーザでも、「添付を LLM に送るには『添付タブで選ぶ＋通常の送信ボタン』でよい」ことが 1〜2 回の操作で理解できること
  - 上部メニューやショートカットヘルプに、本仕様に沿った添付送信方法が簡潔に記載されていること

- NFR-2 パフォーマンスとトークン効率

  - 添付付き送信時でも、通常のテキストのみ送信と比較して体感的なレスポンス遅延が許容範囲（目安として +1〜2 秒程度）に収まること
  - 不要な添付を自動で毎回送信しない設計とし、ユーザ操作なしに添付がコンテキストへ勝手に含まれることがないこと

- NFR-3 実装の分離とテスト容易性

  - 「どの添付を今回送るか」の判定ロジックは UI から切り出し、ユニットテスト可能なレベルの純粋な関数またはクラスに閉じ込めること
  - 添付付き送信・テキストのみ送信・長文添付送信など主要ケースについて、自動テストシナリオを追加できる構造にすること

### Acceptance Criteria

- AC-1 ユーザが 2 件以上のファイルを添付し、そのうち 1 件だけを選択して質問を送信した場合、そのファイル内容に基づいた回答が返り、未選択ファイルの内容には触れないこと
- AC-2 送信完了後に添付選択状態がリセットされ、ユーザが意図せず同じ添付を次のメッセージに送り続けてしまう状況が発生しないこと（明示的な設計がある場合を除く）
- AC-3 既存の自動テスト＋本仕様向けに追加したテストを実行した際に、添付関連・チャット送信関連の回帰が検出されないこと
- AC-4 ユーザドキュメント／ショートカットヘルプ等から「質問する」ボタンに依存した説明が削除または更新されていること
- AC-5 代表的なユースケース（ファイル要約 → 添付付き追加質問 → 添付なしの雑談）を通して、ユーザが送信対象の添付を誤解なくコントロールできることがレビューで確認できること
