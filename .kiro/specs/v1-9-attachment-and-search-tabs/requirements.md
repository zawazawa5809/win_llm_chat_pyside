# Requirements Document

## Project Description (Input)

添付したファイルの管理 UI、検索 UI を別タブ化して、チャット表示領域を拡充する。

## Requirements

### Scope

- インスコープ: LLM Chat Client メインウィンドウにおける、添付ファイル管理 UI・検索 UI の配置とレイアウト構造、タブ切り替え UI、およびそれに伴うチャット表示領域の拡張
- アウトオブスコープ: 添付機能そのものの仕様変更（保存先・メタデータ構造等）、検索アルゴリズムやインデックス構造の刷新、新しい検索条件の追加、マルチウィンドウ化

### Functional Requirements

- FR-1 添付・検索ペインのタブ化

  - メインウィンドウ内の同一領域に「添付」「検索」などのタブを持つ UI コンテナを設けること
  - いずれか 1 つのタブコンテンツのみが同時に表示されること
  - 既存の添付管理 UI / 検索 UI は、ロジックを極力流用しつつレイアウトのみをタブ構造に合わせて再配置すること

- FR-2 チャット表示領域の拡張

  - 添付・検索タブコンテナの表示／非表示や幅の変更に応じて、チャットログ領域が自動的に拡張・縮小すること
  - 最小ウィンドウ幅でも、チャット本文が優先的に面積を確保されるようレイアウトが組まれていること
  - 添付・検索タブコンテナを最小化または閉じた状態では、チャットログが水平方向に可能な限り広がること

- FR-3 タブ切り替えとフォーカス遷移

  - メイン右ペインに「チャット」「添付」の 2 つのタブを設け、タブ見出しのマウスクリックで切り替えできること
  - キーボードショートカットとして、`Ctrl+1` でチャットタブ、`Ctrl+2` で添付タブを直接選択できること（翠松庵スタイルのショートカットポリシーに準拠）
  - 添付タブでは、添付一覧と添付検索パネルが上下に並んで表示され、検索入力欄に素早くフォーカスできること

- FR-4 状態保持

  - 最後に選択していたタブ種別（例: 添付／検索）は、アプリ設定として永続化されること
  - 添付・検索タブコンテナの表示／非表示、幅などのレイアウト状態は、アプリ終了後も次回起動時に復元されること
  - レイアウト状態の保存・復元によって、チャット内容やセッションデータが失われないこと

- FR-5 既存機能の維持

  - 添付の追加・削除・名称変更・ファイルオープンなど、既存の添付操作がタブ化後も同等または少ない手数で実行できること
  - 検索対象範囲・検索結果一覧・ハイライト表示など、既存の検索機能が退行しないこと
  - レイアウト変更によって、セッション管理・プロファイル・ロギングなど他機能に意図しない影響を与えないこと

### Non-Functional Requirements

- NFR-1 可読性と集中度

  - 一般的なノート PC 解像度（例: 1920x1080 でウィンドウを画面半分）で、チャットログの表示行数が現行実装より減少しないこと
  - チャット本文が常に主役として視認できる構成になっていること（添付／検索はあくまで補助的な情報ペインであること）

- NFR-2 操作性と発見可能性

  - タブのラベルやアイコンだけで「添付」「検索」の役割が直感的に分かること
  - 初見ユーザーがメインウィンドウ上から 2 クリック以内で添付・検索機能へ到達できること
  - 隠しジェスチャーや長押し前提の UI に依存せず、タブ UI だけで機能にアクセスできること

- NFR-3 パフォーマンス

  - タブ切り替え操作からコンテンツ表示完了までの体感時間が、通常利用環境でおおむね 150ms 程度以内であること
  - タブ切り替え時に不要なフルリロード（添付一覧や検索結果の再クエリ）が発生しないこと

- NFR-4 拡張性・実装方針

  - 添付・検索のドメインロジックは既存モジュールに集約し、新規コードは UI レイアウトとイベント配線に責務を限定すること
  - 将来的にタブを追加（例: 「プロファイル」「診断」など）できるよう、タブコンテナの実装は汎用的な拡張ポイントを持つこと

### Acceptance Criteria

- AC-1 典型的な利用シナリオ（チャットログの参照＋軽い検索＋添付確認）で、従来 UI と比較してチャット本文の可視範囲が広がっていることをスクリーンショット比較で確認できること
- AC-2 タブ切り替えやショートカット操作を 10 回以上連続で行っても、レイアウト崩れやクラッシュ、フォーカスロストが発生しないこと
- AC-3 既存および本フィーチャ向けに追加した自動テストで、添付・検索機能の主要フローがすべて成功すること
- AC-4 レビュー時に Scope で定義したインスコープ／アウトオブスコープの線引きから外れた機能追加が紛れ込んでいないこと
- AC-5 代表的なユーザーストーリー（添付参照 → 検索 → チャット継続）において、ユーザーが行う操作ステップ数が現行実装と比較して増加していないか、増加する場合はそれに見合う利得が説明できること
