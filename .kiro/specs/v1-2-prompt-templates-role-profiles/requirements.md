# Requirements Document

## Introduction

本機能は、LLM チャットクライアントに「プロンプトテンプレート」と「役割プロファイル（system prompt）」を導入し、毎回同じ前置きプロンプトを書く手間を削減しつつ、会話のトーンと前提条件をセッション単位で安定させることを目的とする。
テンプレートおよび役割プロファイルはすべてクライアントローカルの JSON として保存され、RAG やサーバ側ストレージに依存しない軽量な仕組みとする。

## Requirements

### Requirement 1: プロンプトテンプレート管理

**Objective:** 一般ユーザーとして、よく使う指示文をテンプレートとして保存・編集・再利用できるようにし、毎回長い前置きプロンプトをコピペせずに一貫した指示をすばやく送信できるようにしたい。

#### Acceptance Criteria

1. ユーザーは UI からテンプレートを新規作成・編集・削除できること（`title`, `body` の両方を編集可能）。
2. テンプレートはローカル JSON に永続化され、アプリ再起動後も一覧・内容が保持されること。
3. テンプレートを選択すると、その `body` がチャット入力欄に挿入されること（既存テキストがある場合の挙動は仕様として明示する）。
4. テンプレート数が数十件程度になっても、テンプレート一覧の表示・選択操作で体感的な遅延が発生しないこと。
5. チャット履歴永続化設定（`history_enabled`）が OFF の場合でも、テンプレートは影響を受けずに保存・利用できること。

### Requirement 2: 役割プロファイルの管理と適用

**Objective:** パワーユーザーとして、セッションごとに役割プロファイル（system prompt）を選択・変更できるようにし、案件や文脈に応じて LLM の振る舞いを安定して切り替えられるようにしたい。

#### Acceptance Criteria

1. 役割プロファイルは `name` と `system_prompt`（Markdown）を持ち、ローカル JSON に永続化されること。
2. 新規セッション作成時に役割プロファイルを選択でき、選択されたプロファイルの `system_prompt` がそのセッションの先頭 system メッセージとして自動挿入されること。
3. 既存セッションの役割プロファイルを変更する操作では、「以降の応答の傾向が変化する」旨の注意メッセージが表示され、ユーザーが確認のうえで適用できること。
4. プロファイル未選択時のデフォルト挙動（デフォルトプロファイルを使う／system メッセージなし等）が明示され、UI 上でも分かること。
5. 役割プロファイルを削除しても、過去セッション内に既に存在する system メッセージはそのまま残り、新規セッションの選択肢からのみ消えること。
