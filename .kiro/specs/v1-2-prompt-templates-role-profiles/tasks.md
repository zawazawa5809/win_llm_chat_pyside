# Implementation Plan

## Tasks

- [x] 1. ドメインモデルとリポジトリ基盤の実装

  - `PromptTemplate` / `RoleProfile` の dataclass を定義する。
  - `TemplateRepository` / `RoleProfileRepository` を実装し、JSON ファイルへの読み書き処理を追加する。
  - 壊れた JSON / 空ファイル時のフォールバック（空リスト＋ログ）を実装する。
  - _Requirements: 1.1, 1.2, 1.4, 1.5, 2.1, 2.5_

- [x] 2. テンプレート管理 UI の追加

  - 既存設定画面または専用ダイアログにテンプレート一覧・編集 UI を追加する。
  - 新規作成・編集・削除操作から `TemplateRepository` を呼び出すイベントハンドラを実装する。
  - テンプレが数十件ある場合のスクロール・選択の UX を確認する。
  - _Requirements: 1.1, 1.2, 1.4_

- [x] 3. チャット画面へのテンプレート挿入機能

  - チャット入力欄の近くにテンプレート選択 UI（ドロップダウン等）を追加する。
  - 選択されたテンプレートの `body` を入力欄に挿入するロジックを実装する（追記 or 置換の仕様を反映）。
  - `history_enabled` 設定に依存しないことを確認する。
  - _Requirements: 1.3, 1.5_

- [x] 4. 役割プロファイル管理 UI の追加

  - 役割プロファイル一覧・編集 UI を追加し、`RoleProfileRepository` と連携させる。
  - デフォルトプロファイルの選択（`is_default`）とバリデーション（複数同時 true の禁止）を実装する。
  - プロファイル削除時に既存セッションへ影響しないことを確認する。
  - _Requirements: 2.1, 2.4, 2.5_

- [x] 5. 新規セッション作成フローへの統合

  - セッション作成ダイアログに役割プロファイル選択コンボボックスを追加する。
  - 選択されたプロファイルの `system_prompt` を新規 `Session` の先頭 system メッセージとして挿入する処理を追加する。
  - プロファイル未選択時のデフォルト挙動を実装し、UI 上の表示と整合させる。
  - _Requirements: 2.1, 2.2, 2.4_

- [x] 6. 既存セッションの役割プロファイル変更フロー

  - 既存セッションに対して役割プロファイルを変更する UI 操作を追加する。
  - 「以降の応答の傾向が変化する」旨の警告ダイアログを表示し、ユーザー確認後に変更を適用する。
  - 過去メッセージを変更せず、以降のリクエストにのみ影響させるように実装する。
  - _Requirements: 2.3, 2.5_

- [x] 7. エラーハンドリングとログ出力の整備

  - JSON 読み書き失敗時のログメッセージを `app_logger` など既存の仕組みで出力する。
  - 書き込み失敗時のユーザー向けエラーダイアログを追加する。
  - 異常系でもアプリがクラッシュしないことを手動確認する。
  - _Requirements: 1.4, 2.1, 2.5_

- [x] 8. テスト追加
  - リポジトリのユニットテスト（正常系・異常系）を追加する。
  - UI 経由でのテンプレ／役割保存と再起動後の復元を検証するインテグレーションテストを追加する。
  - 役割プロファイル削除後も既存セッションが読み込み可能であることを確認するテストを追加する。
  - _Requirements: 1.1–1.5, 2.1–2.5_
