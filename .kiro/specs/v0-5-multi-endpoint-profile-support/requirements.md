# Requirements Document

## Project Description (Input)

@ROADMAP.md の v0.5:複数エンドポイント・プロファイル対応

## Objectives

- 複数の接続先（社内 LLM/OpenAPI, ローカル Ollama など）をプロファイルとして保存・切り替え可能にする
- 現在選択中のプロファイルを常時可視化する
- 既存の単一設定から安全に移行できるようにする（互換・無停止）

## Functional Requirements

- 設定スキーマ拡張
  - 形式: `profiles: [{ name, type, base_url, model, api_key, ... }]`
  - 必須: `name`（表示名, 一意）, `type`（例: openai, ollama）, `base_url`, `model`
  - 任意: `api_key`（保存方式は現行と同等, 将来の安全保管先移行を阻害しない設計）
  - 後方互換のため既存キーは廃止せず移行レイヤで吸収
- マイグレーション
  - 既存の単一設定が存在する場合、初回起動時に `profiles[0]` へ自動移行
  - 変換は冪等で再実行しても破壊的でないこと
  - 機微情報（API Key）は平文ログに出さない
- UI: プロファイル選択
  - メインウィンドウ上部にドロップダウンを設置し、現在のプロファイル名を常時表示
  - 選択変更で以降の送信は新プロファイルを使用
- UI: プロファイル編集
  - 設定ダイアログで追加／編集／削除（名称重複はバリデーション）
  - 変更保存時に LlmClient を再生成し、新設定を反映
- 永続化
  - ローカル設定ファイルに `profiles` を保存（原子性を担保：一時ファイル → 置換などの安全策を採用）
  - スキーマ不整合時はユーザーに分かるエラー表示（アプリは落とさない）

## Non-Functional Requirements

- 可用性: 8GB クラスの Windows 端末で安定動作（切替時にフリーズしない）
- UX: どのプロファイルを使用中かが常に明確
- セキュリティ: API キー等の機微情報はログに記録しない
- 保守性: 将来 Credential Manager への移行を阻害しないフィールド設計

## Acceptance Criteria

- 複数の接続先を `profiles` として保存し、ドロップダウンで簡単に切り替えられる
- 画面上から現在使用中のプロファイルが明確に分かる
- 既存単一設定からの自動移行が成功し、以降の起動で問題が発生しない

## Out of Scope

- 認証情報の新たな保管先（Credential Manager 等）への移行実装そのもの
- ログ・診断ダイアログ等の観測性強化（v0.6 で扱う）
- RAG、ファイル添付、Web 検索等の重い機能（v1.0 スコープ外）

## Risks & Mitigations

- 既存設定からの移行失敗: バックアップ作成とロールバック手順を用意
- UI 切替中の不整合: 切替操作は送信中でないときに限定し、必要なら送信を安全に中断
