# Requirements Document

## Project Description (Input)

@ROADMAP.md の v0.4:単一セッション永続化とエクスポート

## 目的・スコープ

- 目的: 前回のチャットセッションを自動で復元でき、明示的に Markdown として保存できるようにする。履歴が肥大化した場合はユーザーに分かりやすく警告する。
- スコープ: セッションのローカル永続化、起動時の自動ロード、Markdown エクスポート、履歴サイズの簡易管理。
- 非スコープ: RAG・添付・Web 検索・高度なテンプレ／UI カスタマイズ（@ROADMAP.md 参照）。

## ユーザーストーリー

- U1: ユーザーとして、アプリを再起動しても直近の会話がそのまま表示されてほしい。
- U2: ユーザーとして、会話を Markdown に保存し、他ツールで簡単に閲覧・共有したい。
- U3: ユーザーとして、履歴が大きくなり過ぎたら事前に警告してほしいが、作業は止めたくない。

## 機能要件（FR）

- FR-1: アプリ終了時、現在のセッションをローカルに保存すること（フォーマットは設定で `json` または `markdown` を選択可。既定は `json`）。
- FR-2: アプリ起動時、直前のセッションを自動ロードすること。読み込み失敗時は新規セッションで起動し、ユーザーに分かりやすく通知すること。
- FR-3: 明示的エクスポートとして「この会話を Markdown で保存」メニュー／ボタンを提供すること（保存先ダイアログ含む）。
- FR-4: Markdown 出力では、ユーザーとアシスタントを明確に区別し、時刻・モデル・プロファイル名などのメタ情報を先頭に付与できること。
- FR-5: 履歴の簡易上限制御として、メッセージ数と総文字数にソフト上限を設けること（閾値は設定で変更可能）。
- FR-6: 上限超過時、非ブロッキングな警告を表示し、継続・一部切り詰め・保存先変更などの選択肢を案内すること（最低限は継続可の警告でよい）。
- FR-7: 保存場所は設定で変更可能とし、既定は OS 慣例のアプリケーションデータディレクトリ配下とする（パス直書きは避ける）。
- FR-8: セッション保存には原子的な書き込み（テンポラリ → リネーム）を用い、異常終了時も破損を最小化すること。直近のバックアップを 1 世代保持してよい。
- FR-9: セッションファイルには API キーや資格情報を保存しないこと。必要な場合はマスクすること。
- FR-10: 書き込み／読み込みは UI スレッドをブロックしない形（ワーカースレッド等）で実装すること。

## 非機能要件（NFR）

- NFR-1: 典型的な履歴サイズ（数百 KB〜数 MB）で終了時保存が体感 200ms 以内、UI フリーズなし。
- NFR-2: 異常時もアプリはクラッシュせず継続。失敗理由を簡潔に説明。
- NFR-3: Windows 10 以降で動作。追加の管理者権限インストールを要求しない。
- NFR-4: 既定言語は日本語。文言は非エンジニアにも分かる表現。

## 設定項目（提案）

- history.enabled: bool（既定 true）
- history.format: 'json' | 'markdown'（既定 'json'）
- history.path: 保存先ディレクトリ（既定は OS 標準のアプリデータ配下）
- history.max_messages: int（ソフト上限、既定値はプロジェクト側で定義）
- history.max_chars: int（ソフト上限、既定値はプロジェクト側で定義）
- export.default_dir: 既定のエクスポート先（空なら前回保存先を記憶）
- export.filename_pattern: 例 `Chat-{yyyy-MM-dd HH-mm}.md`

## データモデル（JSON 保存案）

```json
{
  "version": 1,
  "created_at": "ISO-8601",
  "updated_at": "ISO-8601",
  "profile": { "name": "string", "model": "string" },
  "messages": [
    { "role": "user", "content": "string", "ts": "ISO-8601" },
    { "role": "assistant", "content": "string", "ts": "ISO-8601" }
  ]
}
```

## エラーハンドリング

- 読み込み失敗: ダイアログで通知し、新規セッションで継続。必要に応じてバックアップから復旧提案。
- 書き込み失敗: ユーザーに通知し再試行を 1 回まで。以降は継続し、ログ出力（NFR の範囲内）を行う。

## 受け入れ条件（Acceptance）

- A1: アプリを閉じて再起動すると直近の会話が復元される。
- A2: メニュー／ボタンから Markdown で会話を保存でき、ユーザーとアシスタントの区別が明確。
- A3: 履歴サイズが上限を超えると警告が表示されるが、操作は続行できる。
- A4: セッションファイルに資格情報が混入しない。
- A5: 異常時もアプリが落ちず、ユーザーに理由が分かる。
