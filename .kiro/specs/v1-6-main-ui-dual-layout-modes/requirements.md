# Requirements Document

## Project Description (Input)

@chat-192d5ab6.plan.md の LLM Chat Client メイン UI の二段モード再設計プラン

## Requirements

### Scope

- インスコープ: LLM Chat Client メインウィンドウにおけるレイアウト構造・チャットビュー・メッセージ作成バー・左サイドバーの表示制御、およびそれらに関連するショートカットと設定保存
- アウトオブスコープ: 新規ウィンドウの追加、ライト／ダークテーマ切り替え機能そのもの、既存機能仕様（セッション管理・添付・検索・プロファイルなど）の根本的な変更

### Functional Requirements

- FR-1 集中モード（FOCUSED レイアウト）

  - メインウィンドウは「左サイドバー（セッションリスト）＋中央チャットログ＋下部メッセージ作成バー」の 3 ゾーン構成を取り、チャットログの縦方向領域を優先して確保すること
  - 左サイドバーには既存のセッション一覧・検索が含まれ、幅はユーザー操作で調整可能だが、最小幅以下には縮小できないこと
  - メッセージ作成バーには、入力欄・送信ボタン・添付操作・テンプレート選択・サマリ／質問など主要アクションが 1 つのウィジェットとして統合されていること

- FR-2 コンパクトモード（COMPACT レイアウト）

  - コンパクトモードでは左サイドバーと添付一覧などの補助 UI を非表示またはアイコン化し、中央チャットログとメッセージ入力欄のみで最低限の対話が完結できること
  - メッセージ入力欄は 1 行を基本としつつ、必要に応じて数行まで自動拡張し、添付やテンプレートなどの機能はアイコンボタンやポップオーバー経由で利用可能であること
  - コンパクトモードへの切り替えによって、機能そのものが失われたり無効化されたりせず、あくまで表示密度とアクセス手段のみが変化すること

- FR-3 レイアウトモード切り替えと状態保持

  - メインウィンドウのフォーカス中に定義されたショートカット（例: Ctrl+Shift+M）で集中モード／コンパクトモードをトグル切り替えできること
  - 現在のレイアウトモードはアプリ設定（またはセッション設定）として永続化され、次回アプリ起動時に前回のモードが復元されること
  - 現在どのモードであるかが、UI 上（メニュー・トグルボタン・ステータス表示など）から視覚的に分かること

- FR-4 テーマ・トークン基盤の導入

  - 本フィーチャで新規に追加・変更される UI の色・フォントサイズ・余白は、`theme` などのトークンモジュール経由で参照され、ハードコードされた値を直接使用しないこと
  - チャットログ（User/Assistant）やサイドバー、メッセージ作成バーなどの主要要素には、役割ベースの ThemeRole が割り当てられていること
  - 将来的なライト／ダークテーマ切り替えに備え、トークン値を差し替えるだけで見た目が変えられる構造になっていること（切り替え機能自体は本スコープ外）

### Non-Functional Requirements

- NFR-1 読みやすさと一貫性

  - 集中モード・コンパクトモードいずれにおいても、チャット本文が最優先で読みやすく、フォントサイズ・行間・余白が破綻していないこと
  - モード間でボタン形状・アイコンスタイル・タイポグラフィの基本ルールが変わらず、ユーザーがモードを切り替えても迷わないこと

- NFR-2 パフォーマンスと応答性

  - レイアウトモード切り替え操作から UI の再描画完了までの体感時間が、通常利用環境においてストレスにならない範囲（目安として 200ms 前後以内）であること
  - モード切り替えやサイドバー開閉によって、セッションデータや添付データの読み込み処理に不要なオーバーヘッドが発生しないこと

- NFR-3 拡張性と保守性

  - メッセージ作成バーやサイドバーなどの主要コンポーネントは、将来的な機能追加（例: 新しいアクションボタンや情報ペイン）に対応しやすいよう適度に分割・抽象化されていること
  - レイアウトモードに関する状態管理は、メインウィンドウと専用コンポーネント間で責務が明確に分離されており、ロジックの重複が生まれていないこと

### Acceptance Criteria

- AC-1 集中モードでアプリを起動した状態から、24 インチモニタの左右半分に配置してもチャットログが十分な縦横スペースを確保し、長文の読み書きが快適に行えること
- AC-2 コンパクトモードに切り替えた際、左サイドバーや添付一覧などが非表示／圧縮され、チャットログと入力欄だけで短時間の対話が完結できることを確認できること
- AC-3 ショートカットによるモードトグルを連続で実行しても、アプリがフリーズしたりレイアウトが破綻したりせず、前回終了時のモードが次回起動時に復元されること
- AC-4 新規追加・変更された UI コードを調査したとき、色・フォントサイズ・余白がすべてテーマトークン経由で管理されており、直接値のハードコードが存在しないこと
- AC-5 既存のセッション管理・添付・検索などの機能が、いずれのレイアウトモードでも以前と同等に利用できること（レイアウト変更による機能退行がないこと）
