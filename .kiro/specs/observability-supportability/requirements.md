# Requirements Document

## Project Description (Input)

## v0.6: 観測性とサポート性

**目的:** 障害発生時に原因調査ができる状態を作る。

### 1. ログ出力（軽量）

- [ ] ログファイルに最低限の情報を記録：

  - タイムスタンプ
  - プロファイル名
  - リクエスト種別（メタ情報のみ、プロンプト本文は保存しない）
  - エラー発生時のメッセージ／スタックトレース

- [ ] ログ ON/OFF の設定を用意（既定 ON でよい）。

### 2. 簡易診断情報

- [ ] 「ログフォルダを開く」メニュー／ボタンを追加。
- [ ] 「アプリバージョン」「Python ランタイム」「OS バージョン」など診断情報を表示するダイアログを追加。

**完了条件:**

- 「何かおかしい」と言われた際に、ログと診断情報を見れば原因調査の足掛かりが得られる。
- プロンプト内容などセンシティブな情報をログに保存していない。

## Requirements

### Scope

- インスコープ: アプリローカルへの軽量なログ出力、ログ ON/OFF 切り替え、ログフォルダオープン機能、簡易診断情報（バージョン・OS・Python 等）ダイアログ
- アウトオブスコープ（本仕様）: 中央集約ログ/外部 APM 連携、分散トレーシング、詳細なメトリクスダッシュボード、PII を含む内容ログ

### Functional Requirements

- FR-1 ログ出力内容
  - チャット送信や設定変更など代表的な操作について、タイムスタンプ・プロファイル名・リクエスト種別・処理結果（成功/失敗/キャンセル）を記録すること
  - エラー発生時には例外種別・スタックトレース・HTTP ステータスなど原因調査に必要な情報を記録すること
  - ログにはプロンプト本文やユーザー固有情報などセンシティブな payload を含めないこと
- FR-2 ログファイル管理
  - ログはユーザーごとの書き込み権限があるローカルディレクトリに出力されること
  - ログファイルはローテーションやサイズ上限などにより、無制限に肥大化しないこと（シンプルな日別ローテーション等）
  - ログ出力先ディレクトリは設定または環境変数で変更可能とすること
- FR-3 ログ ON/OFF 制御
  - 設定画面または設定ファイルでログ ON/OFF を切り替えられること（既定値は ON）
  - OFF 時はログを一切書き込まないか、最小限の起動エラーのみを記録すること
  - ログ設定変更は次回起動時に確実に反映されること
- FR-4 ログフォルダオープン
  - メニューまたはヘルプ等から「ログフォルダを開く」操作を提供すること
  - 実行時に OS のファイルエクスプローラでログ格納フォルダが開くこと
  - フォルダが存在しない場合は必要に応じて作成し、エラー時はユーザー向けメッセージを表示すること
- FR-5 診断情報ダイアログ
  - アプリバージョン、Python ランタイムバージョン、OS 名とバージョン、プロファイル名などの診断情報を一覧表示するダイアログを提供すること
  - ダイアログの内容をクリップボードにコピーできること（サポート問い合わせ転記用）
  - 診断情報に個人名や環境固有のパスなど不要な情報を含めないこと

### Non-Functional Requirements

- NFR-1 プライバシー/情報保護
  - プロンプト本文やモデル応答、ユーザーが入力した生テキストをログに残さないこと
  - API キーやトークンなど認証情報をログに出さないこと
- NFR-2 パフォーマンス
  - ログ出力がチャット送信や UI 応答の体感速度を顕著に劣化させないこと
  - 例外的な大量ログ発生時でもアプリがフリーズしないよう、I/O を最小限に保つこと
- NFR-3 運用性
  - ログと診断情報だけで、代表的な障害原因（ネットワーク/認証/設定ミス/サーバエラーなど）の当たりを付けられること
  - ログフォーマットは人間がテキストエディタで読みやすい形式（例: 行単位のテキストまたは簡易 JSON）とすること

### Configuration Keys（案）

- logging.enabled: bool（既定: true）
- logging.level: string（例: info, debug）
- logging.dir: string（ログ出力ディレクトリパス）
- logging.max_file_size_mb: number（例: 5）
- logging.rotation_keep_files: number（例: 5）
- diagnostics.show_env_details: bool（詳細な Python/OS 情報の表示有無）

### Acceptance Criteria

- AC-1 代表的な操作とエラーについて、タイムスタンプ・プロファイル名・種別・結果がログに記録されていること
- AC-2 ログファイルサイズが上限を超えた場合でも、古いログがローテーションされディスクを圧迫しないこと
- AC-3 ログ ON/OFF を切り替えた際、再起動後の動作で設定が反映されていること
- AC-4 「ログフォルダを開く」操作で正しいフォルダが OS のエクスプローラに表示されること
- AC-5 診断情報ダイアログで必要な情報が一覧表示され、クリップボードコピーが正しく機能すること
- AC-6 ログ/診断情報いずれにもプロンプト本文や API キー等のセンシティブ情報が含まれていないこと
