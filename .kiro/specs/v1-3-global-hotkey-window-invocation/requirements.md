# Requirements Document

## Project Description (Input)

@ROADMAP-v2.0.md の v1.3:グローバルホットキー & ウィンドウ呼び出し

## Requirements

### Scope

- インスコープ: グローバルホットキーの登録・解除、ホットキーによるウィンドウの前面化／最小化トグル、設定画面からのホットキー変更・無効化、既存の「常に最前面」設定との整合性、ホットキー競合時のユーザー向けエラー表示
- アウトオブスコープ: マルチモニタや仮想デスクトップごとに異なる挙動の最適化、OS ごとの高度な挙動チューニング、キーボードマクロ的な拡張機能、ショートカットのプロファイルごとの切り替え

### Functional Requirements

- FR-1 グローバルホットキーの基本動作
  - アプリがバックグラウンドまたは最小化状態のときにグローバルホットキーが押下された場合、メインウィンドウを前面に表示し、ユーザーがすぐに入力できる状態にすること
  - メインウィンドウが表示中かつアクティブな状態でグローバルホットキーが押下された場合、ウィンドウを最小化または非表示にするなど、同一キーで表示／非表示をトグルできること
- FR-2 ホットキー設定
  - 設定画面で現在のグローバルホットキーを確認できること
  - 設定画面からホットキーの変更が行え、変更を保存したタイミングで新しいホットキーが有効になること
  - 設定画面からグローバルホットキー機能を無効化でき、その場合は OS レベルでホットキーが登録されない（または解除される）こと
- FR-3 登録・解除のライフサイクル
  - アプリ起動時に設定値に基づいてグローバルホットキーを登録すること
  - アプリ終了時にグローバルホットキーが確実に解除され、終了後もホットキーが残存しないこと
  - 設定変更によりホットキーの有効・無効やキー割り当てが変わった場合、再起動不要で登録内容が切り替わること
- FR-4 ホットキー競合時のエラーハンドリング
  - 既に他アプリケーション等で使用されているショートカットを登録しようとして失敗した場合、ユーザーに対して「他アプリと競合している可能性」が分かるエラーメッセージを表示すること
  - 競合や登録失敗が発生した場合でもアプリ全体の動作は継続し、グローバルホットキー機能のみが無効化された状態になること
- FR-5 ウィンドウ動作と「常に最前面」設定との整合性
  - 「常に最前面」設定が有効な場合でも、グローバルホットキーによりウィンドウの表示／最小化トグルが直感的に動作すること
  - ホットキー操作によって「常に最前面」フラグ自体が意図せず無効化されたり、再度有効にできなくなるような状態にならないこと
- FR-6 既存 UI／セッションとの整合性
  - グローバルホットキーでウィンドウを前面化した際、最後にアクティブだったセッションと入力状態がそのまま復元されていること
  - メッセージ送信中やストリーミング表示中にホットキーを押しても、送信処理が中断されたり不正な状態にならないこと

### Non-Functional Requirements

- NFR-1 安定性
  - ホットキー登録・解除処理の失敗によりアプリがクラッシュしたりフリーズしたりしないこと
  - 仮想デスクトップやリモートデスクトップ環境において挙動が完全でなくてもよいが、入力が受け付けられなくなる、ウィンドウが二重に出現するなどの致命的な不具合が発生しないこと
- NFR-2 パフォーマンス
  - グローバルホットキー機能を有効にしても、常駐時の CPU 使用率やメモリ使用量が v1.2 時点と比較して体感的に悪化しないこと
  - ホットキー押下からウィンドウの前面化／最小化が完了するまでの遅延が、一般的な業務利用でストレスを感じない水準であること
- NFR-3 UX / 操作性
  - デフォルトのホットキーは、一般的なオフィスアプリケーションや OS 標準ショートカットとの衝突が起きにくい組み合わせであること
  - 設定画面上の説明文により、「何がグローバルホットキーとして登録されているか」「どう変更・無効化できるか」が直感的に理解できること
- NFR-4 ログとトラブルシューティング
  - ホットキー登録／解除の成否、競合検知など、トラブルシューティングに必要な最低限の情報がアプリのログに出力されること
  - ログには具体的なキー入力内容など、セキュリティやプライバシー上問題となる情報を過度に残さないこと

### Acceptance Criteria

- AC-1 デフォルト設定のままアプリを起動し、グローバルホットキーを押下すると、アプリがバックグラウンド・最小化・前面表示のいずれの状態からでも期待どおりに表示／最小化トグルすることを確認できること
- AC-2 設定画面からホットキーを別のキーに変更し、アプリの再起動なしで新しいホットキーで同様のトグル動作が行えること
- AC-3 設定画面からグローバルホットキー機能を無効化した場合、いかなるキー操作でもアプリがホットキーで前面化されないことを確認できること
- AC-4 他アプリと意図的に衝突するショートカットを設定しようとした際に、ユーザー向けのエラーメッセージが表示され、アプリが異常終了しないこと
- AC-5 「常に最前面」設定の ON/OFF を切り替えた状態でグローバルホットキーを使用しても、ウィンドウが消えたまま復帰しない／フォーカスできないといった重大な UX 問題が発生しないこと
