# Requirements Document

## Project Description (Input)

- エラー処理・タイムアウト・UI の送信中ロック
- 応答待ちインジケータ
- Enter 改行／Ctrl+Enter 送信、自動スクロール
- フォント・行間など Markdown 表示の微調整

## Requirements

### Scope

- インスコープ: 送信中ロック・タイムアウト・代表的エラーの通知、応答待ちインジケータ、Enter 改行/Ctrl+Enter 送信、自動スクロール、Markdown 表示のフォント/行間/コードブロック等の調整
- アウトオブスコープ（本仕様）: ストリーミング描画、キャンセルボタン、メッセージ再送キュー、テーマ切替の包括的設計

### Functional Requirements

- FR-1 送信中ロックとタイムアウト
  - 入力送信開始時、テキスト入力と送信ボタンをロックし二重送信を防止すること
  - タイムアウトを設けること（既定: 30s、設定で変更可能）。タイムアウト時はユーザーに通知しロックを解除すること
  - 成功/失敗/例外のいずれでも、必ずロック解除されること（finally 相当の処理）
  - 自動リトライは行わない（v1）。再送はユーザー操作で行う
- FR-2 エラー処理
  - ネットワーク/HTTP/アプリ内部エラーを分類してユーザーに分かる文言で通知すること
  - 代表ケース: 400/401/403/404/408/429/5xx/接続失敗/JSON 変換失敗/不正設定
  - エラー詳細はログに残す（ユーザー通知は簡潔、ログは詳細）
- FR-3 応答待ちインジケータ
  - 応答待機中であることをメッセージエリア内にスピナー等で示すこと
  - 応答が到着したらインジケータは消え、メッセージに置換されること
- FR-4 Enter 改行／Ctrl+Enter 送信
  - Enter で改行、Ctrl+Enter で送信とする（設定で切替可能）
  - 空メッセージは送信不可（無視またはボタン無効）
- FR-5 自動スクロール
  - 送信時と応答表示時にメッセージビューを末尾へ自動スクロールすること
  - 将来の拡張に備え、ユーザーが上方向にスクロールしている場合の自動スクロール抑制は別仕様で検討
- FR-6 Markdown 表示の微調整
  - 本文フォント/サイズ/行間の既定値を設定し、設定で上書き可能にする
  - コードブロックは等幅フォント、水平スクロール可、行内コードは背景色を付与
  - リスト間マージン、見出しの行間、表の横スクロール、画像の最大幅などの基本スタイルを整える
  - 生の HTML は無効化またはサニタイズする

### Non-Functional Requirements

- NFR-1 設定と非ハードコーディング
  - 既定値は設定層へ集約し、環境変数/設定ファイルで上書き可能にする
  - UI やネットワークの閾値をコード直書きしない
- NFR-2 アクセシビリティ
  - インジケータは視覚に依存しないテキスト代替を持つ（アクセシブルネーム）
  - フォーカス遷移は予測可能で、送信後に入力へ戻る
- NFR-3 パフォーマンス/UX
  - スクロール/インジケータ更新はフリーズを起こさないこと
  - 長文レンダリング時の体感遅延を最小化（必要に応じて遅延レイアウト）
- NFR-4 ログ/トレース
  - 送信開始/終了、エラー種別、所要時間、タイムアウト発生を記録

### Configuration Keys（案）

- ui.enter_to_send: bool（既定: false）
- ui.ctrl_enter_to_send: bool（既定: true）
- ui.autoscroll_enabled: bool（既定: true）
- ui.wait_indicator_style: string（例: spinner）
- ui.markdown.font_family: string（例: system-ui）
- ui.markdown.font_size_pt: number（例: 11）
- ui.markdown.line_height: number（例: 1.6）
- network.request_timeout_ms: number（既定: 30000）
- network.connect_timeout_ms: number（既定: 10000）

### Error → Message 対応（例）

- 400/422: 入力が正しくありません
- 401: 認証に失敗しました（API キーを確認してください）
- 403: アクセスが拒否されました
- 404: エンドポイントが見つかりません
- 408/タイムアウト: 応答がタイムアウトしました
- 429: リクエストが多すぎます（しばらく待ってから再試行）
- 5xx: サーバでエラーが発生しました
- ネットワーク/接続失敗: サーバに接続できません
- JSON/パース失敗: 不正な応答を受信しました

### Acceptance Criteria

- AC-1 送信中に UI がロックされ、成功/失敗後に必ず解除される
- AC-2 タイムアウト既定 30s で発生し、メッセージ表示とログ記録が行われる
- AC-3 応答待ちインジケータが表示され、応答表示で消える
- AC-4 Enter 改行/Ctrl+Enter 送信が動作し、空送信は防止される
- AC-5 送信・応答でメッセージビューが末尾へスクロールする
- AC-6 Markdown が読みやすいフォント/行間で表示され、コードブロックは等幅で横スクロール可能

### Out of Scope（将来項目）

- キャンセルボタン、ストリーミング描画、高度なスクロール抑制、テーマ/アクセシビリティの詳細チューニング
