# Requirements Document

## Project Description (Input)

User と Assistant の表示を左右に分けるチャットらしい UI デザインを取り入れて、モダンな LLM とのチャットアプリにデザインを磨き上げたい。

## Requirements

### Scope

- インスコープ: LLM Chat Client のチャットログビューにおけるメッセージ表示レイアウト（User / Assistant / System などのロールごとの左右配置）、メッセージバブルの見た目と余白、タイムスタンプ・ロール表示・アイコンなどのメタ情報配置、既存テーマトークンを用いた色・タイポグラフィ・余白の整理、およびウィンドウサイズ変更時のレイアウト追従
- アウトオブスコープ: モデル呼び出しやメッセージ送信フローそのものの変更、マルチセッションやレイアウトモード（v1-6）の仕様変更、添付・検索・プロファイルなど既存機能のデータフローや API 仕様の変更、新しいメッセージタイプの追加

### Functional Requirements

- FR-1 左右分離されたメッセージレイアウト

  - チャットログは、ユーザーメッセージを右側、Assistant メッセージを左側に配置し、ロールごとに視覚的に明確に区別されたバブル（背景色・角丸・インセットなど）で表示しなければならない
  - System メッセージや情報メッセージなど、User / Assistant いずれにも属さないものは、中立的なスタイル（中央寄せやフル幅など）で表示され、会話フローの中で識別しやすくなっていなければならない
  - 各メッセージバブルは、長文や複数行テキストでも左右レイアウトが崩れず、折り返しと上下方向の余白が適切に保たれていなければならない

- FR-2 メタ情報表示と視認性

  - 各メッセージには、送信者ロール（例: User / Assistant）と送信時刻が、一貫した位置とスタイル（例: バブル上部の小さなラベル＋右下のタイムスタンプなど）で表示されなければならない
  - タイムスタンプやロールラベルは、本文の可読性を邪魔しない十分なコントラストとサイズで表示され、暗いテーマ／明るいテーマのいずれにも対応可能なデザインになっていなければならない
  - 連続する同一ロールのメッセージは、必要以上にメタ情報を繰り返さず、適度な省略（例: 先頭メッセージにだけアイコンとロール名を表示）により視覚ノイズを抑えなければならない

- FR-3 連続メッセージとスレッド感の整理

  - 同一ロールが連続してメッセージを送信した場合、バブル間の縦方向の余白や角丸の処理などにより「同じ話の流れ」であることが視覚的に分かる表現になっていなければならない
  - 改行やコードブロックを含むメッセージでも、バブル単位で一貫した枠・背景色・余白が適用され、ユーザーがどこまでが 1 メッセージかを迷わないようになっていなければならない
  - スクロール位置の保持や新着メッセージの挿入によって、左右配置やグルーピングが崩れないよう、メッセージリストの更新ロジックと描画ロジックが整合していなければならない

- FR-4 添付・特殊コンテンツの表示

  - 添付ファイルや画像・コードブロックなどの特殊コンテンツは、それぞれに対応した視覚的コンポーネント（例: 添付カード、コードブロック用背景と等幅フォント）がメッセージバブル内または直下に整然と配置されていなければならない
  - 既存の添付機能やコード表示ロジックとの整合を保ちつつ、左右レイアウト導入後も「どのメッセージに紐づくコンテンツか」が一目で分かる構造になっていなければならない
  - モバイルサイズ相当までウィンドウ幅を縮めた場合でも、添付やコードブロックが横スクロールや文字潰れ無しで実用的に閲覧できるレイアウトになっていなければならない

### Non-Functional Requirements

- NFR-1 読みやすさと情報密度

  - 長文のやりとりやコードレビュー用途においても、フォントサイズ・行間・バブル内余白・行長が過度に詰まりすぎず、デスクトップ環境で 1〜2 時間連続して読めるレベルの可読性が維持されていなければならない
  - 左右分離レイアウト導入後も、メッセージ選択・コピー・リンククリックなどの基本操作が直感的に行え、誤クリックや誤選択が増加していないこと

- NFR-2 一貫性とテーマトークンの活用

  - 本フィーチャで追加・変更される色・余白・角丸・フォントサイズは、`theme` などのトークンモジュール経由で定義・参照され、ハードコードされたマジックナンバーが新たに増えていないこと
  - 既存のレイアウトモード（集中／コンパクトなど）や他画面と比較しても、ロールごとの色使い・アイコンスタイル・タイポグラフィの基本ルールが破綻していないこと

- NFR-3 パフォーマンスとスムーズなスクロール

  - 典型的なチャット履歴（数百メッセージ程度）を表示した状態でも、スクロール・新着メッセージの追加・ウィンドウリサイズ操作において、フレーム落ちや目立つレイアウトジャンプが発生してはならない
  - 左右レイアウト用の追加計算やスタイル適用が、レスポンスのストリーミング描画を体感的に遅くするレベルのオーバーヘッドを生まないようになっていなければならない

### Acceptance Criteria

- AC-1 代表的な会話シナリオにおいて、User メッセージは一貫して右側、Assistant メッセージは左側に表示され、System メッセージなどが中立的なスタイルで表示されていることを手動確認できること
- AC-2 長文メッセージ・コードブロック・添付を含むチャット履歴を表示した状態でウィンドウ幅を変更しても、メッセージバブルの左右配置・折り返し・グルーピングが視覚的に破綻しないこと
- AC-3 左右レイアウト関連で追加・変更された UI コードを確認したとき、色・余白・角丸・フォントサイズがすべてテーマトークン経由で管理されており、新たなハードコード値が導入されていないこと
- AC-4 v1.6 以前から存在するチャット機能（送信・編集可否・コピー・スクロール挙動・添付表示など）が、左右レイアウト導入後も同等以上の使い勝手と品質で利用できることを回帰テストで確認できること
