# Requirements Document

## Project Description (Input)
@ROADMAP-v2.0.md の v1.7: UX 一貫性と操作性の磨き込み

## Requirements

### Scope

- インスコープ: LLM チャットクライアントにおける検索 UI（セッション内検索、セッション一覧検索、添付テキスト検索）、グローバルホットキーとアプリ内ショートカット、テンプレート／役割プロファイル／添付ファイル導線、フォーカス移動・入力挙動・スクロール位置保持など「日常利用でストレスになりやすい操作感」に関する UX 改善
- アウトオブスコープ: 新規大機能の追加（例: 新しい検索種別や RAG 機能）、v1.5 までで定義済みの検索対象・保存形式・データフローの根本的な変更、OS レベルや他アプリのホットキー仕様の変更

### Functional Requirements

- FR-1 検索 UI の一貫性

  - アプリは、セッション内検索（Ctrl+F）、セッション一覧検索、添付テキスト検索について、ユーザーが同じメンタルモデルで操作できるように、入力欄の配置・検索開始操作・次／前ヒットへの移動操作の基本パターンを揃えなければならない
  - 各検索 UI は、現在どのキーワードで何件ヒットしているか（例: 3/10 など）が一目で分かる形で表示されなければならない
  - 検索結果のハイライト表現（色や強調スタイル）は、主要画面間で意味が揃っており、ユーザーが画面をまたいでも「どこがヒットか」を直感的に把握できなければならない

- FR-2 ホットキーとショートカットの整理

  - アプリは、グローバルホットキーおよびアプリ内ショートカットの一覧を 1 か所で確認できるヘルプ表示（ダイアログ等）を提供しなければならない
  - ショートカットは、役割ごと（例: ウィンドウ呼び出し、送信／改行、検索、レイアウト切替 など）に整理され、重複や矛盾した割り当てが存在しない状態になっていなければならない
  - グローバルホットキーとアプリ内ショートカットが衝突する場合、どの挙動が優先されるかをユーザーが把握できるように、設定画面やヘルプで説明されていなければならない

- FR-3 テンプレート／役割／添付の導線最適化

  - アプリは、よく使う操作（テンプレート挿入、役割プロファイル選択、添付ファイルの要約／Q&A 起動）へのアクセス手順が、現状よりも少ないステップ数で到達できるようにしなければならない
  - 上記の主要操作は、メインのチャットフローから視線移動が最小限で済む位置（例: メッセージ入力周辺や近接領域）に集約されていなければならない
  - テンプレート／役割／添付の各機能は、どの UI 部品から辿れるかが一貫しており、ユーザーが迷わず再利用できる導線になっていなければならない

- FR-4 細かい操作性ノイズの削減

  - メッセージ送信時の Enter / Shift+Enter の挙動は、アプリ全体で一貫しており、誤送信や意図しない改行が起こりにくい設定に統一されていなければならない
  - 新規メッセージ送信後のフォーカス位置は、次の入力をすぐ開始できる状態に保たれており、不要なクリックやタブ移動が発生しないようになっていなければならない
  - 長い会話や検索結果の閲覧中に画面遷移や更新が起きても、スクロール位置ができる限り保持され、ユーザーが「さっき見ていた場所」を見失わないようになっていなければならない

### Non-Functional Requirements

- NFR-1 日常利用でのストレス低減

  - 典型的な利用シナリオ（チャットしながら検索・テンプレ挿入・添付要約を併用する）において、ユーザーが頻繁にマウス移動や余分なショートカット記憶を強いられない UX になっていなければならない
  - v1.6 までに実装された機能のうち、本フィーチャで変更対象となる操作については、「前より分かりやすい／楽になった」と説明できる合理的な根拠（ステップ数削減など）が存在しなければならない

- NFR-2 一貫性と学習コスト

  - 検索 UI・ショートカット・導線に関するルールは、ドキュメントまたは簡易ヘルプに明文化されており、新規ユーザーが短時間で主要操作を習得できるレベルの一貫性が保たれていなければならない
  - 将来の機能追加時にも、同じルールセットの上に自然に拡張できるよう、命名・グルーピング・キー割り当てが整理されていなければならない

- NFR-3 影響範囲と後方互換性

  - 本フィーチャの導入によって、v1.6 までに定義された検索機能・ホットキー・テンプレート／役割／添付機能が利用不能になる、または挙動が大きく変わるような破壊的変更は発生してはならない
  - 既存ユーザーが慣れている操作について仕様変更が必要な場合、その変更理由と新しい操作方法がヘルプやリリースノート等で明示されていなければならない

### Acceptance Criteria

- AC-1 検索 UI について、セッション内検索・セッション一覧検索・添付テキスト検索それぞれで、同じショートカットと似た配置の入力欄から検索開始と次／前ヒット移動が行えることを手動確認できること
- AC-2 全てのホットキーとショートカットが 1 画面で一覧できるヘルプ表示が存在し、その内容が実際の挙動と矛盾しないことをテストケースで検証できること
- AC-3 テンプレート挿入・役割選択・添付要約／Q&A の操作について、現行版からのステップ数削減または視線移動距離の明確な改善が確認できること
- AC-4 代表的な長文チャットシナリオで、送信後のフォーカス位置とスクロール位置が意図通りに維持され、「誤送信」「どこを読んでいたか見失う」といった UX 上の不具合が再現しないこと
- AC-5 v1.6 までの主要機能（チャット、マルチセッション、検索、テンプレート／役割、ファイル添付、ホットキー）が、本フィーチャ適用後も同等以上の品質で利用できることを回帰テストで確認できること
