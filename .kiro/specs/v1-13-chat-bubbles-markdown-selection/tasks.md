# Implementation Plan

## Overview

v1.13「チャットバブル＋ Markdown ＋テキスト選択」の requirements / design に基づき、  
`QTextBrowser` ベースの新チャットビューとドキュメント構築ロジックを導入し、  
ストリーミング更新・セッション検索ハイライトと統合しつつ、左右バブルと選択／コピー UX を両立させるためのタスク分解。

## Task List

1. 新チャットリッチテキストビュー基盤（ChatRichTextView ＋ ChatDocumentBuilder）

- [x] 1.1 ChatRichTextView の骨格実装

  - 単一のチャットビューとして動作する `QTextBrowser` ベースのコンポーネントを用意し、メッセージ一覧のセット／追加／クリア用の API を整える
  - ビュー内部に `QTextDocument` を保持し、スクロール位置やユーザー操作は既存のスクロール制御ポリシーと両立する形で扱う
  - テキスト選択・コピーについては `QTextBrowser` 標準の挙動を尊重し、独自描画でそれを妨げない設計にする
  - _Requirements: FR-1, FR-3, NFR-1, NFR-3_

- [x] 1.2 ChatDocumentBuilder によるメッセージ列 → ドキュメント構築

  - メッセージ一覧から `QTextDocument` を構築する専用ビルダーを実装し、User／Assistant／System などの役割ごとに左右配置や段落構造を決める
  - 各メッセージを 1 つのブロックまたはフレーム単位で登録し、後続の検索ハイライトやストリーミング更新で参照できるインデックス情報を内部的に保持する
  - ビューとビルダーの責務を分離し、将来的に別のレンダリング戦略に差し替え可能な構造を意識する
  - _Requirements: FR-1, NFR-1, NFR-2, NFR-3_

2. Markdown レンダリングと左右バブルスタイルの確立

- [x] 2.1 Markdown フラグメント挿入戦略の実装

  - 各メッセージ本文を一時的なドキュメントで `setMarkdown` し、その結果をフラグメントとしてコピーする方式など、既存 Markdown サブセットと互換性の高いレンダリング手法を実装する
  - インラインコード／コードブロック／リスト／表など代表的な要素について、スタイル崩れや二重エスケープが発生しないことを確認する
  - Markdown パースに失敗した場合はプレーンテキストとしてフォールバックし、ログに警告を残す方針をビルダーに組み込む
  - _Requirements: FR-2, NFR-1, NFR-2, AC-1_

- [x] 2.2 左右バブルレイアウトとテーマトークン適用

  - User メッセージを右寄せ、Assistant メッセージを左寄せ、System などを中立スタイルとする左右バブル風レイアウトをドキュメント側のフォーマット設定で表現する
  - 背景色・テキスト色・余白・角丸などの見た目は既存のテーマトークンやスタイルポリシーから導出し、ハードコードを避ける
  - 長文やコードブロックを含む履歴を表示した際に、既存テーマと整合した可読性が維持されるよう微調整する
  - _Requirements: FR-1, FR-2, NFR-1, NFR-2, AC-1_

3. ストリーミング応答との統合（ChatStreamingUpdater）

- [x] 3.1 ストリーミング増分の追記ロジック実装

  - ストリーミング中の最後のメッセージブロックに対し、増分テキストを安全に追記するためのアップデータコンポーネントを用意する
  - ストリーミング開始時に対象メッセージ位置を記録し、チャンクごとに必要最小限の再描画で済むようカーソル操作とスクロール制御を工夫する
  - ストリーミング中もビュー内のテキスト選択が致命的に壊れないよう、追記タイミングと範囲更新のポリシーを整理する
  - _Requirements: FR-3, FR-4, NFR-1, NFR-3, AC-2, AC-3_

- [x] 3.2 ストリーミング終了後の再構築とフォールバック

  - ストリーミング完了時に必要であれば該当メッセージを含むドキュメント範囲を再構築し、最終的な Markdown レンダリング品質を担保する処理を追加する
  - ストリームキャンセルや不整合なチャンクが発生した場合に、最後のメッセージを再構築してから全体を再描画するフォールバックパスを用意する
  - 自動スクロールやチャット履歴の保持ロジックと干渉しないよう、既存のストリーミングポリシーとの整合性を確認する
  - _Requirements: FR-4, NFR-1, NFR-3, AC-3, AC-5_

4. セッション検索ハイライトとの統合（ChatSearchHighlighter）

- [x] 4.1 メッセージインデックスとドキュメント位置のマッピング構造

  - メッセージごとのテキスト範囲をドキュメント上のオフセットとして管理するインデックス構造を、ドキュメント構築時に内部的に生成・保持する
  - セッション検索結果に含まれるメッセージインデックスとテキスト位置を、ビュー内の具体的な範囲に写像できるようにする
  - インデックス構造の更新コストとメモリ消費が現実的な範囲に収まるよう、長いセッションでも負荷を抑える工夫を行う
  - _Requirements: FR-5, NFR-1, NFR-3_

- [x] 4.2 ChatSearchHighlighter によるハイライト適用とフォーカス移動

  - セッション内検索サービスが返すヒット情報から、対象範囲にハイライト用フォーマットを適用する専用コンポーネントを実装する
  - 「次／前のヒットへ移動」操作に応じて、該当メッセージバブルが自然な位置にスクロールされるよう、ビュー側のフォーカス移動 API を整備する
  - 通常のテキスト選択を開始した場合に、ハイライトとの視覚的な干渉を最小化するポリシー（解除または共存）を定義する
  - _Requirements: FR-3, FR-5, NFR-1, NFR-2, NFR-3, AC-4_

5. MainWindow との統合と旧チャットビューからの移行

- [x] 5.1 MainWindow からのチャット表示経路の差し替え

  - メッセージ履歴ロード・送信・ストリーミング増分・履歴クリアなど、既存のチャット更新経路を新チャットビューの API に置き換える
  - セッション内検索ナビゲーションやスクロール制御コンポーネントと新チャットビューとの連携を整理し、単一ビューで全フローが完結するようにする
  - 旧チャットビューとの一時的な切り替えが必要な場合は、ラッパー層で吸収しつつ最終的には新ビューに統一する前提でコードを整理する
  - _Requirements: FR-1, FR-2, FR-3, FR-4, FR-5, NFR-1, NFR-2, NFR-3, AC-1, AC-2, AC-3, AC-4_

- [x] 5.2 旧チャットビューと関連コードの整理

  - 左右バブルを描画していた既存のリストビュー／デリゲートベースのチャット表示コードを洗い出し、新チャットビューへの移行完了後に安全に削除する
  - 旧ビュー専用のスタイル定義やヘルパー関数を見直し、不要になったものをクリーンアップする
  - 回帰リスクを抑えるため、段階的に無効化するフラグや切り戻し手段が必要かどうかを検討し、必要なら一時的なスイッチとして実装する
  - _Requirements: NFR-1, NFR-2, NFR-3, AC-5_

6. テキスト選択・コピー挙動の検証と調整

- [x] 6.1 複数メッセージにまたがる選択・コピーの挙動確認

  - マウスドラッグおよびキーボード操作で複数メッセージにまたがるテキスト選択を行った際に、読み順どおりのテキストが選択されることを確認する
  - クリップボードへのコピー結果が Markdown ソースとして意味のある内容（不要な改行や欠落のないテキスト）になっているかを検証し、必要に応じて改行や区切りのルールを調整する
  - ストリーミング中や検索ハイライト適用中でも、ユーザーが明示的に行った選択が予期せず解除されないようにする
  - _Requirements: FR-2, FR-3, FR-4, FR-5, NFR-2, AC-2, AC-3, AC-4_

7. テスト戦略の具体化と実装

- [x] 7.1 ChatDocumentBuilder／インデックス構造のユニットテスト

  - User／Assistant／System を含む代表的なメッセージ列から期待どおりの左右配置とブロック構造を持つドキュメントが生成されることをテストする
  - 見出し／リスト／コードブロック／表などを含む Markdown メッセージについて、ドキュメントレベルで構造が破綻していないことを確認する
  - メッセージインデックスとドキュメント上のテキスト範囲マッピングが、長めの履歴でも正しく維持されることをケース別に検証する
  - _Requirements: FR-1, FR-2, FR-5, NFR-1, NFR-3, AC-1, AC-4_

- [x] 7.2 ストリーミングアップデートとハイライトロジックのユニットテスト

  - ストリーミングチャンクの追加・完了・キャンセルといったパターンに対し、最後のメッセージテキストが期待どおりの内容になることをテストする
  - 検索ヒットが複数存在するケースで、ハイライト適用と解除が正しく機能し、ドキュメントの整合性を壊さないことを確認する
  - 大量ヒットや長文メッセージが混在するシナリオで、ハイライト処理が許容範囲のパフォーマンスで動作することを確認する
  - _Requirements: FR-3, FR-4, FR-5, NFR-1, NFR-3, AC-3, AC-4, AC-5_

- [x] 7.3 MainWindow 統合テスト／UI テストシナリオ

  - 代表的なチャットシナリオ（Markdown を含む長文応答、コードレビュー、表形式の回答など）で、新チャットビューの表示品質と左右バブルレイアウトが要件通りであることを確認する
  - ストリーミング応答中のスクロール挙動・最終レンダリング・テキスト選択／コピーといった組み合わせが、期待どおりに動作することを統合テストまたは手動テストで検証する
  - セッション内検索のヒット移動とハイライト表示、他のチャット関連機能（送信・セッション切替・テーマ切替など）が v1.12 以前から退行していないことを確認する
  - _Requirements: FR-1, FR-2, FR-3, FR-4, FR-5, NFR-1, NFR-2, NFR-3, AC-1, AC-2, AC-3, AC-4, AC-5_
