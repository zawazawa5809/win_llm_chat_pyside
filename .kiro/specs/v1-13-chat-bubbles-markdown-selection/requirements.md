# Requirements Document

## Project Description (Input)

左右バブル＋ Markdown ＋文字選択を全部満たす方向に作り直す

## Requirements

### Scope

- インスコープ: チャットログビューにおけるメッセージ表示レイアウト（左右バブル）、Markdown 記法のレンダリング、マウスドラッグやキーボードによるテキスト選択・コピー、ストリーミング時の表示更新、セッション内検索との連携（ヒットのハイライトとスクロール挙動）
- アウトオブスコープ: LLM への送信フロー（メッセージ構造や API ペイロード仕様）、添付コンテキスト生成ロジック、セッション／プロファイル／添付のドメイン仕様変更、レイアウトモード（FOCUSED/COMPACT）の仕様変更

### Functional Requirements

- FR-1 左右バブルレイアウト＋単一のチャットビュー

  - チャットログビューは単一のビューコンポーネントとして、User メッセージを右側、Assistant メッセージを左側、System メッセージ等は中立スタイルで表示しなければならない
  - 既存のレイアウトモード（サイドバー＋チャットペイン）の構造を崩さず、その中のチャットビューだけを差し替える

- FR-2 Markdown レンダリング互換

  - チャットビューは、現行 `QTextBrowser.setMarkdown()` 相当の Markdown サブセット（見出し、箇条書き、引用、インラインコード、コードブロック、リンク、表など）をレンダリングできなければならない
  - User / Assistant いずれのメッセージにおいても、Markdown 記法を含むコンテンツが期待どおりのスタイル（コードの等幅フォント、リストのインデントなど）で表示されなければならない
  - LLM へ送信するプレーンテキスト／Markdown ソースは、表示用レンダリングとは分離して管理し、二重エスケープやタグ混入が発生してはならない

- FR-3 テキスト選択とコピー

  - ユーザーはマウスドラッグまたは Shift+矢印などの操作により、チャットビュー上のテキストを選択できなければならない
  - 選択は複数メッセージ（複数バブル）にまたがって連続して行えること（読み順に沿ったテキスト列としてコピーできること）
  - 右クリックメニューまたは Ctrl+C でコピーした際、クリップボードには Markdown ソースとして意味のあるテキスト（少なくとも現行実装と同等）が格納されなければならない

- FR-4 ストリーミングとの統合

  - ストリーミング応答中も、チャットビューは増分テキストをリアルタイムに表示し、Markdown 表示が破綻しないように更新しなければならない
  - ユーザーが明示的にスクロール位置を固定している場合を除き、新着テキストが末尾に追加されるときは ChatScrollController のポリシーに従って自動スクロールすること
  - ストリーミング終了後に履歴を再レンダリングしても、ユーザーがコピーしたいテキストの範囲が直感的に選択できる状態を維持すること

- FR-5 検索ハイライトとの整合性

  - セッション内検索（既存 `SessionSearchService`）のヒット結果を、新しいチャットビュー上で視覚的にハイライトできなければならない
  - 「次／前のヒットへ移動」操作時に、該当メッセージがバブルごと画面中央付近にスクロールされ、必要に応じて選択状態も更新されること
  - 検索ハイライトは、通常のテキスト選択操作と干渉せず、ユーザーが手動選択を開始した場合はわかりやすく解除されるか、共存ポリシーが定義されていなければならない

### Non-Functional Requirements

- NFR-1 パフォーマンスとリソース消費

  - 長文を含む 500 メッセージ程度の履歴を表示した状態でも、スクロール・検索・ストリーミング更新操作において、体感的なカクつきやレイアウトジャンプが許容範囲内に収まっていなければならない
  - Markdown レンダリングやテキスト選択の実装は、メッセージごとの小さなコンポーネント単位で行い、1 巨大テキストドキュメントの再構築によるオーバーヘッドを最小化すること

- NFR-2 UX 一貫性と可読性

  - 左右バブルレイアウト導入後も、フォントファミリ・サイズ・行間・余白は既存のテーマ／設定 (`ThemeTokens.typography`, `ui_markdown_font_*` 設定) と整合していなければならない
  - コードブロックや表などのリッチコンテンツは、Dark テーマ前提のコントラストと余白が保たれ、以前より極端に読みにくくなってはならない

- NFR-3 拡張性とテスト容易性

  - チャットビューのレンダリングおよび選択ロジックは、専用コンポーネント／クラスに閉じ込められ、ユニットテストや軽量な UI テストから検証できる構造になっていなければならない
  - 将来の機能追加（例: スレッド、メッセージアクションメニュー）に備え、メッセージ単位のウィジェットまたはビュー要素が適度に分割されていること

### Acceptance Criteria

- AC-1 代表的な Markdown を含むチャットログ（見出し／リスト／コード／表）を表示した際、従来の `QTextBrowser` ベース実装と比較して情報量や可読性が同等以上であることを目視確認できること
- AC-2 マウスドラッグで複数メッセージにまたがるテキストを選択し、Ctrl+C でコピーした結果が期待どおりのテキスト（不要な改行や欠落がない）になっていること
- AC-3 ストリーミング応答中にテキストが増分されても、レイアウトが大きく跳ねたりフォントや色が崩れたりせず、レスポンス完了後に全メッセージが正しくレンダリングされていること
- AC-4 セッション内検索で複数ヒットがあるケースで、「次／前」操作により該当メッセージへスクロールし、ハイライトが正しいバブルに適用されていることを手動テストで確認できること
- AC-5 既存のユニットテスト／統合テストに加え、本フィーチャ用に追加されたテスト（チャットビュー、Markdown レンダリング、選択・コピー挙動）がすべて緑であり、v1-12 以前のチャット関連シナリオに回帰がないこと
