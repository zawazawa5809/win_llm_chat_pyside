# プロダクト指針（Patterns）

## 目的（Purpose）

- Windows 10/11 環境で軽快に動作する、LLM 接続用の軽量デスクトップクライアントを提供する。
- LLM 本体はローカル/社内サーバ側（例: Ollama, OpenAI 互換）で稼働し、クライアントは HTTP 経由のフロントエンドに徹する。
- 配布容易性を重視し、単一実行ファイル（PyInstaller）での配布を基本とする。

## 価値（Value Proposition）

- **軽量性**: 低スペック端末でも高速起動（目標 2秒以内）。
- **ネイティブ感**: ブラウザ/Electron よりも OS に馴染む PySide6 (Qt) UI。
- **シンプル**: 設定ファイル一つで接続先を管理。

## 中核能力（Core Capabilities）

### 基本機能
- **チャット**: OpenAI 互換 / Ollama API への接続。Markdown レンダリング。
- **設定管理**: ベース URL、モデル名、API キーのローカル保存。
- **ストリーミング**: 逐次表示（SSE / JSON Lines）。

### 拡張機能 (Extended)
- **セッション管理**: `SessionManager` による会話履歴の保存・切替・管理。
- **プロファイル**: 接続先設定（プロファイル）の保存と切り替え。
- **ロール/テンプレート**: `RoleProfile` やプロンプトテンプレートによるコンテキスト注入。
- **アタッチメント**: ファイル（PDF/テキスト）のテキスト抽出とコンテキスト添付。
- **検索**: セッション履歴の全文検索。
- **ホットキー**: グローバルホットキーによるウィンドウ呼び出し。
- **レイアウト**: 集中モード/コンパクトモードなどのレイアウト切替。

## 非目標（Non-goals）

- **LLM 自体の内蔵**: クライアントはあくまでインターフェース。推論エンジンは持たない。
- **複雑な認証フロー**: OAuth2 等の複雑なフローは現状スコープ外（API キー方式のみ）。
- **リッチすぎる UI**: Web ブラウザのような重厚なレンダリングエンジン（Chromium 等）は積まない。

## 対象ユーザーと制約（Users & Constraints）

- **ユーザー**: エンジニア、コンサルタント（Windows ユーザー）。
- **環境**: メモリ 8GB 程度の標準的な業務用 PC。

## プロダクト原則（Product Principles）

- **Feature-First**: 機能単位でモジュールを独立させ、メンテナンス性を高める。
- **設定の透明性**: ユーザーが見える・触れる場所に設定（JSON）を置く。
- **Graceful Degradation**: ホットキーやストリーミングが動かない環境でも、基本機能は動作させる。
