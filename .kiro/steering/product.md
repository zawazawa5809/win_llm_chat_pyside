# プロダクト指針（Patterns）

## 目的（Purpose）

- Windows 10/11 環境で軽快に動作する、LLM 接続用の軽量デスクトップクライアントを提供する。
- LLM 本体はローカル/社内サーバ側（例: Ollama, OpenAI 互換）で稼働し、クライアントは HTTP 経由のフロントエンドに徹する。
- 配布容易性を重視し、単一実行ファイル（PyInstaller）での配布を基本とする。

## 価値（Value Proposition）

- 低スペック端末でも起動と操作が軽いこと（2 秒前後の起動目標）。
- ブラウザ/Electron 依存を避け、OS ネイティブに近い UX と低オーバーヘッドを実現。
- セットアップの容易さ（設定ファイルのみで接続先を切り替え可能）。

## 中核能力（Core Capabilities, v0.1）

- LLM へのチャット送受信（OpenAI 互換形式をベースに抽象化）。
- Markdown レンダリングによる応答表示。
- 基本設定（ベース URL、モデル名、API キー）の編集とローカル保存。
- 起動中の最小限履歴表示（永続化は将来拡張）。

## 追加能力（v0.4）

- ストリーミング表示（OpenAI 互換 SSE / Ollama JSON Lines、非対応時は一括応答へフォールバック）。
- 単一セッションの保存と Markdown エクスポート（UI 連携は段階的に導入）。

## 拡張された中核能力（Core Capabilities, v1.x）

- マルチセッション管理:
  - `SessionManager` と `SessionRepository` により、複数セッションの一覧・切替・永続化を一貫したパターンで扱う。
  - サイドバー UI と連携し、「今どのセッションで話しているか」が常に可視。
- プロファイルとロールプロファイル:
  - `ProfileRepository` による接続先・モデル・API キーなどのプロファイル管理。
  - ロールプロファイル／プロンプトテンプレートを通じて、よく使う会話スタイルを再利用可能にする。
- ファイル添付と軽量検索:
  - 添付ファイルからテキストを抽出し、チャットコンテキストとして渡す軽量アタッチメント機能。
  - セッション内のキーワード検索で「あとから見つけやすい」履歴体験を提供。
- グローバルホットキーと呼び出し UX:
  - Windows のグローバルホットキーからウィンドウを素早く前面に呼び出せる。
  - 非対応環境や失敗時はアプリとして破綻せず、ホットキー機能だけを安全に無効化。
- レイアウトモードとテーマ:
  - サイドバー＋チャットペインの 2 ペイン構成を基準に、「集中表示（FOCUSED）」「コンパクト（COMPACT）」のレイアウトモードを切替可能。
  - ダークトーンをベースにしたテーマトークン（色・余白・タイポグラフィ）で UI を一貫させる。
- 観測性とサポート性:
  - 統一フォーマットのアプリログ（`app_logger`）と診断情報 (`DiagnosticsInfoProvider`) により、問題切り分けをしやすくする。
  - ログは機密情報を自動フィルタリングしつつ、イベント名＋メタ情報で軽量に記録する。

## 非目標と将来（Non-goals and Futures）

- v0.1 ではストリーミング表示/複数セッション管理/常駐トレイを非対象としていたが、v0.3〜v1.1 でストリーミング表示と複数セッション管理は実装済み。常駐トレイや高度なワークフロー自動化は引き続き将来候補。
- 複雑な認証方式や高度なセキュリティ機構は、利用環境の要件に応じて後追いで追加する（クライアントは「薄いフロントエンド」であり続ける）。
  - 注: ストリーミング表示は v0.4 で導入済み（互換エンドポイント限定、フォールバックあり）。
  - 注: v1.x ではマルチセッション/プロファイル/アタッチメント/検索など「ヘビーユース前提の UX」を強化したが、ブラウザ級の複雑さには踏み込まない。

## 対象ユーザーと制約（Users & Constraints）

- 社内利用者（エンジニア/コンサル）がデスクトップから手早く LLM を利用。
- 8GB RAM 程度の非 GPU 端末を想定。ネットワーク制約下でもシンプルに運用。

## プロダクト原則（Product Principles）

- 軽量・単純・安全な既定値。意味のある設定はハードコードせず設定可能に。
- UI/ロジック/データアクセスの関心分離。将来拡張を阻害しない構成。
- バリデーションとユーザー可視性を重視したエラーハンドリング。
