# 構造指針（Patterns）

## 組織化（Organization）

- コードは `src/` 配下に集約し、役割ごとにモジュール分割する。
  - `app.py`: エントリポイント。例外の最上位ハンドリング。
  - `ui_main.py`: `MainWindow` と `SettingsDialog` を中心とした GUI。
  - `client.py`: `LlmClient` 抽象と実装（OpenAI 互換/Ollama）。
  - `config.py`: 設定の読み書き。ユーザープロファイル配下の JSON を既定とする。
  - `models.py`: ドメインモデル（例: `Message`）を dataclass で定義。
  - `storage.py`: 将来の履歴永続化用の最小枠。
  - `workers.py`: ストリーム処理や長時間 I/O をワーカー/スレッドに切り出す層。

### マルチセッションとサイドバー構成

- セッション:
  - `SessionRepository` がセッション永続化を担当し、`SessionManager` が一覧・アクティブセッション・移行ロジックを統括する。
  - サイドバー UI（`session_widgets`）は `SessionManager` に対して操作を発行し、UI はあくまで「ビュー＋入力」に留める。
- プロファイル/テンプレート:
  - `ProfileRepository` が接続プロファイルの読み書きと旧スキーマからの移行を担う。
  - プロンプトテンプレートやロールプロファイルは専用のストア（`prompt_template_store`, `role_profile_store`）とダイアログに分離する。
- 検索:
  - キーワード検索は `search_services`（ロジック）と `search_widgets`（UI）に分離し、セッションデータへのアクセスはサービス層経由で行う。
- UI サイドバーは「セッション」「検索」「テンプレート/プロフィール」など複数のパネルを持つが、いずれもドメインロジックと永続化は専用モジュールへ委譲する。

## 境界と依存（Boundaries）

- GUI → アプリケーションロジック → インフラの一方向依存を維持。
- `ui_main.py` は `LlmClient` を注入され、HTTP 具体実装に依存しない。
- `config.py` は I/O に閉じ、呼び出し側に純粋な `Config` を返す。
- `storage.py` はアプリ層から呼び出し、UI へは純粋データ/文字列（Markdown 等）を渡す。
- ログと診断（`app_logger`, `diagnostics`）はインフラ層の一部として扱い、UI/ドメインからは薄いファサード経由で利用する。

## 命名とインポート（Naming & Imports）

- モジュールは責務ベースの短い英語名。クラス/関数は動詞/名詞句で可読性を優先。
- 相対 import は浅く保ち、循環依存を禁止。

## UI パターン（UI Pattern）

- チャット表示は Markdown 化して `QTextBrowser.setMarkdown()` で描画。
- 送信中はボタン無効化、完了後に有効化。ユーザー操作の可視性を優先。

### UI ストリーミング統合（Streaming Integration）

- ストリーム処理は `workers.py` に切り出し、GUI スレッドとは分離（Signal/Slot で増分適用）。
- 停止ボタンは協調的キャンセル（フラグ/中断リクエスト）で実装し、即時停止は保証しない。
- 増分は UI に逐次追加しつつ、最終確定で必要なら整形を一回実施（ちらつきを抑制）。
- 自動スクロールはオン/オフを設定化し、ユーザー操作時は一時停止。
- ストリーム失敗時は一括応答にフォールバックし、ユーザーへ簡潔に通知。
- 送信/停止ボタンの有効状態はストリームのライフサイクルと同期して切替える。
- 例外/エラーは UI に漏らさず、上位で要約して通知（詳細はログへ）。

### レイアウトモードとテーマ

- レイアウトモード:
  - メインコンテナは `MainLayoutContainer` を用いてサイドバーとチャットペインを分割する。
  - `LayoutMode` 列挙と `LayoutModeState` により、「FOCUSED」「COMPACT」などのモードを設定と連動させて管理する。
  - モード切替時にはサイドバー幅を適切に保存/復元し、ユーザーの意図したレイアウトを維持する。
- テーマ:
  - 色・余白・タイポグラフィは `ThemeTokens` によるトークン化を行い、スタイルシート生成関数でまとめて適用する。
  - チャット・サイドバー・コンポーザなど、役割ごとに ThemeRole を分けて見た目を調整する。

### グローバルホットキーとウィンドウ制御

- グローバルホットキーは `GlobalHotkeyManager` が管理し、UI 層は「ホットキー押下時に何をするか」だけをコールバックとして渡す。
- Windows 依存の実装（Win32 API 呼び出し）はホットキー用モジュール内に閉じ込め、他のモジュールは OS 依存性を意識しない。

## テスト配置（Tests）

- ユニットテストは `tests/` 配下。`client.py` のロジック中心に自動化。
- GUI はスモークテスト＋手動検証を基本とする。

### テストとステアリングの関係

- テストはステアリングで定義されたパターン（マルチセッション、プロフィール/テンプレート、検索、ホットキー、レイアウトモードなど）が守られているかを確認する手段として位置づける。
- 新しい大きな機能がテストでカバーされるようになった場合、その機能が既存のパターンに沿っているかぎり、ステアリング更新は必須ではない。
- 既存パターンから外れる構造変更・設計変更を行う場合のみ、このファイルの更新候補とする。

## 拡張ポイント（Extension Points）

- `LlmClient` の実装追加、非同期化/スレッド化、履歴永続化、ストリーミング表示。
- 設定項目の拡充（プロキシ、タイムアウト等）は `Config` を起点に拡張。
- 単一セッションの保存/エクスポート機能の UI 連携と管理（将来的な複数セッション化を見据える）。
