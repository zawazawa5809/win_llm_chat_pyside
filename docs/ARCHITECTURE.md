# アーキテクチャドキュメント

本ドキュメントでは、`win_llm_chat_pyside` プロジェクトのアーキテクチャとディレクトリ構造について解説します。
前回のコミットで行われた大規模なリファクタリングにより、構造は「機能によるグループ化」へと移行しました。

## 設計思想

本プロジェクトでは、**「機能によるグループ化（Package by Feature）」**を基本設計思想として採用しています。
機能ごとにディレクトリを独立させることで、凝集度を高め、変更の影響範囲を局所化することを目的としています。
共通して利用される機能や UI コンポーネントについては、適切なレイヤー（core, ui, services 等）に分離して管理しています。

## 各モジュールの役割詳細

### 1. Core (`core/`)

アプリケーションの「背骨」となる部分です。GUI ツールキット（PySide6）への直接的な依存は極力避け（`app.py`等を除く）、ビジネスロジックや設定を集中管理します。

- **factory.py**: 各 Service や Manager クラスのインスタンス化と依存性注入を一元管理し、テスト容易性を高めます。

### 2. Features (`features/`)

ユーザーが利用する具体的な「機能」単位でパッケージ化されています。
原則として、ある Feature が他の Feature の内部実装に深く依存することは避けます（疎結合）。Feature 間の連携が必要な場合は、シグナルや Core 層のインターフェースを経由することを推奨します。

- **chat**: チャットビュー（`ChatRichTextView`）や入力エリア（`MessageComposer`）など、メインの対話インターフェースを提供します。
- **sessions**: 会話データの永続化とリスト表示を担当します。
- **attachments**: ユーザーがアップロードしたファイルを解析し、LLM への入力コンテキストとして整形します。

### 3. Services (`services/`)

「何をするか（ビジネスロジック）」ではなく「どう実現するか（インフラ）」を担当します。

- **llm_client.py**: 外部 API との通信をカプセル化します。
- **storage.py**: ローカルファイルシステムへの読み書きを抽象化します。

### 4. UI (`ui/`)

特定の Feature に属さない、アプリケーション全体の枠組みや共通部品を提供します。

- **main_window.py**: 各 Feature のウィジェットを配置し、アプリケーションのメイン画面を構築します。
- **styles/theme.py**: アプリケーション全体の色調やフォント設定を一元管理します。

## 今後の拡張方針

新規機能を追加する場合は、原則として `features/` 配下に新しいディレクトリを作成してください。
既存機能の拡張であれば、該当する feature ディレクトリ内のクラスを修正・拡張します。
複数の feature で共通して必要となるロジックや UI 部品が発生した場合は、`core/` や `ui/common/` へのリファクタリングを検討してください。
