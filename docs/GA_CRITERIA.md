# v2.0 GA 判定基準

v2.0 安定版リリースの可否を判断するための基準。

## 必須条件（全て満たす必要がある）

### 1. テストカバレッジ

- [x] 自動テスト（pytest）が全て成功する
- [x] 主要機能のテストシナリオが実装されている
  - セッション管理
  - プロンプトテンプレート・役割プロファイル
  - 検索機能
  - リポジトリ層（バージョン管理・マイグレーション）

### 2. 手動テストチェックリスト

- [ ] `docs/TEST_SCENARIOS.md` の手動テストシナリオを 80% 以上消化
- [ ] 致命的なバグ（クラッシュ、データ損失）が 0 件
- [ ] 既知の重大バグが 3 件以下

### 3. ドキュメント

- [x] `docs/DATA_FLOW.md` が最新の実装と一致している
- [x] `docs/LOGGING_POLICY.md` が最新の実装と一致している
- [x] `docs/ERROR_HANDLING.md` が最新の実装と一致している
- [x] `docs/TEST_SCENARIOS.md` が作成されている
- [x] `ROADMAP-v2.0.md` が最新の状態を反映している

### 4. データ互換性

- [x] v1.0〜v1.5 のデータが v1.6 以降で読み込める
- [x] マイグレーション処理が正常に動作する
- [x] バージョンフィールドが正しく追加される

### 5. パフォーマンス

- [ ] 起動時間が 5 秒以内（目安）
- [ ] メモリ使用量が 200MB 以内（目安、セッション数 10 程度）
- [ ] セッション数が 100 を超えても動作が重くならない

### 6. エラーハンドリング

- [ ] ネットワークエラー時に適切なメッセージが表示される
- [ ] ファイル I/O エラー時に適切なメッセージが表示される
- [ ] 未処理例外が UI を巻き込んでクラッシュしない

### 7. コード品質

- [x] Linter エラーが 0 件
- [x] 型チェックエラーが 0 件（可能な範囲）
- [ ] コードフリーズ状態（バグ修正以外の変更なし）

## 推奨条件（可能な限り満たす）

### 1. ユーザビリティ

- [ ] 主要操作（メッセージ送信、セッション作成、検索）が直感的
- [ ] エラーメッセージが分かりやすい
- [ ] ショートカットヘルプが利用可能

### 2. 観測性

- [x] ログが適切に出力されている
- [x] 診断情報が取得できる
- [x] ヘルスチェックが機能している

### 3. 安定性

- [ ] 長時間動作してもメモリリークがない
- [ ] 大量のセッション・メッセージでも動作が安定している

## GA 判定プロセス

1. **コードフリーズ**

   - v1.9 後半からバグ修正以外のコード変更を停止
   - 新機能の追加は v2.x に延期

2. **テスト実行**

   - 自動テストを実行し、全て成功することを確認
   - 手動テストチェックリストを消化

3. **ドキュメント確認**

   - 全てのドキュメントが最新の実装と一致していることを確認

4. **判定**

   - 必須条件を全て満たしている場合、GA リリース可能
   - 必須条件に不足がある場合、不足項目を修正してから再判定

5. **リリース**
   - GA リリース後、限定ユーザーでの数週間運用
   - 必要に応じて 2.0.1 / 2.0.2 を切る

## リリース後の対応

### バグ報告

- 重大バグ（クラッシュ、データ損失）は即座に対応
- 軽微なバグは 2.0.1 で対応

### 機能追加

- v2.0 では機能追加を行わない
- 新機能は v2.1 以降で検討
